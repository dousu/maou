# 提案: 予算消化の closure・1 doubling あたり Elo の更新・nps 変動の追跡結果を反映する

## Trigger

carry-over の「公称予算の 13.6% しか消化しない」(原因未解明) を，同一設定
(`--ab-mode budget --playouts 6400 --playouts-b 1600`, threads 2, max-moves 512)
の dfpn on/off で測り直した．**現行ビルドでは再現しない**．

| 構成 | 実 playout/手 | 空回り/手 | 消費率 | 空回り比 | throughput |
|---|---|---|---|---|---|
| dfpn on | 2,628 | 913 | **88.5%** | 25.8% | 3,999.6 p/s |
| dfpn off | 3,504 | 372 | **96.9%** | 9.6% | 5,154.4 p/s |
| 旧測定 | — | — | **13.6%** | (空回り込み) | 1,997.2 p/s |

さらに**副次的に大きい発見**があった: 同じ run のハーネス再較正で
`A score 91.7% / A Elo +417 [+105, +729] / t = +5.00` (dfpn on/off の 2 run で
A の成績が完全一致) → **1 doubling あたり +208 Elo [+52, +364]**．
旧値 **60 Elo** は**予算が 13.6% しか届いていない状態で測った値**であり，
A に約束した 4 倍の探索量が実際には届いていなかったため棋力差が圧縮されていた．

これは**優先順位に直接効く**: aggregator の伸びしろ約 2 倍 (= 1 doubling) の
期待値が旧換算の 3.5 倍になる．

## ドキュメント変更内容 (本レビューの承認対象)

### (a) §3.1 を新設 — ハーネス再較正の実測結果

`11W 0D 1L / 91.7% (CI [64.6%, 98.5%]) / +417 [+105, +729] / t = +5.00` と
**1 doubling ≈ +208 Elo [+52, +364]**．**旧値 60 Elo は信用しない**理由
(予算未達で棋力差が圧縮) と，**n=12 の CI は旧 CI と重なるので確定には
n ≥ 24 が要る** (約 35 分) ことを明記．

### (b) §3.2 を新設 — ② の closure

上記の消費率表．**旧測定の 13.6% は再現しない**こと，dfpn は残差 8.4 ポイントを
説明する (`RootProven` による打ち切り) が 86% の欠損は説明しないこと，どの変更が
効いたかは特定できていないが**現行ビルドでは満額届いているので未解明現象としては
閉じる**こと，**再発時はまず消費率 (実 + 空回り ÷ 公称) を出す**こと (空回り分離前は
「消費」と「水増し」が読めなかった) を記載．副産物として **dfpn の throughput
コスト −22.4%** と空回り 2.7 倍も記録．

### (c) §4.5 の期待値換算に注記

`+1.34% ≈ +1.2 Elo` は旧換算 (60)．**208 で換算しても +4.1 Elo** で検出限界の
1-2 桁下なので**結論 (棄却) は変わらない**ことを明記．

### (d) §5.1 に aggregator の価値を追記

伸びしろ約 2 倍 = 1 doubling 相当 ⇒ **+208 Elo 級**の期待値 (旧換算の 3.5 倍)
= **現時点で最も期待値の大きい未着手項目**．着手前に §3 を n ≥ 24 で回して換算
係数を締めること．

### (e) §1 の nps 変動 (2.2 倍低下) の追跡結果

計測器 (`avg_batch` / `collisions`) を入れた直後に同一コマンドを 4 連続で回した:

| threads | run1 | run2 |
|---|---|---|
| 2 | 10,096 p/s | 10,074 p/s |
| 1 | 10,049 p/s | 10,010 p/s |

**±0.4% で安定**し，**4,595 は再現しない**．したがって 2.2 倍低下は
**一過性の外れ値**で，会計・充填率のいずれでもない (充填率は本測定でも未取得 —
Colab の wheel が計測器追加前だったため)．§1 の記述を「原因未特定」から
「**一過性で再現せず．同一 session 内では ±0.4% で安定**」へ更新し，
**天井は同一 session で測り直す**規則と計測器の読み方 (充填率・衝突) は
次回のために残す．

なお `--threads 1` と `2` の差は 0.5% 以内で，**長い単発探索では 2 スレッド目が
効かない** (自己対局の短い探索で threads 2 が約 4 割遅いという既知の実測と
矛盾しない — あちらはバッチが埋まらない regime の話)．

## 代替案と棄却理由

- **② を「未解明」のまま残す**: 棄却．現行ビルドで満額消化している以上，追跡
  対象としての意味がない．再発時の初手 (消費率を出す) だけ残せば足りる．
- **旧 60 Elo を残して併記だけする**: 棄却．§4/§6 の期待値計算に使う係数なので，
  どちらを使うか曖昧にすると読み手が誤る．**旧値は信用しないと明示**して
  新値を採る (ただし CI の広さも書く)．
- **n=24 で測り直してから docs へ書く**: 棄却しないが後続．消費率の closure は
  今の run で確定しており，Elo 係数だけが精度不足．「点推定 208・CI 広い・確定は
  n ≥ 24」と書けば誤読の余地はない．
- **dfpn を既定 off にする** (throughput −22.4% を避ける): 棄却．探索の質
  (詰み検出) と速度のトレードオフは既に「実配置で切る理由はない」と結論済み
  (§5.1)．本レビューは数値の更新のみ．

## リスクと理由

- **risk: low** — 実測値の記述追加のみ．コード・既定値は変えない．
- **reversibility: trivial** — 追記した §3.1 / §3.2 と 2 箇所の注記を戻すだけ．
