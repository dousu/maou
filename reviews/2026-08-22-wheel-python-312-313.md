# 提案: サポート Python を 3.12/3.13 に移し，docs の cp311/cp312 記述を追随させる

## 背景 (user 課題, 2026-08-22)

Colab のデフォルト Python が **3.13** になった．現行の
`build-wheel.yml` は `-i python3.11 python3.12` で cp311/cp312 しか
出さないため，Colab の既定環境に入る wheel が無い．

## 実施したコード変更 (docs 対象外・本提案とは別コミット)

| ファイル | 変更 |
|---|---|
| `pyproject.toml` | `requires-python = ">=3.11,<3.13"` → `">=3.12,<3.14"`，version 0.98.3 → 0.99.0 |
| `pyproject.toml` (dev) | `cshogi>=0.9.2` → `cshogi>=1.0.4` |
| `.github/workflows/build-wheel.yml` | `-i python3.11 python3.12` → `-i python3.12 python3.13`，release notes の `CPython 3.11, 3.12` → `3.12, 3.13` |
| `.github/workflows/build-wheel-windows.yml` | matrix `["3.11","3.12"]` → `["3.12","3.13"]` |
| `uv.lock` | 再解決 (onnx 1.20.1 → 1.22.0，ml-dtypes 0.5.4 → 0.5.4/0.6.0 fork) |
| `src/maou/app/learning/{callbacks,network}.py`，`src/maou/app/utility/dataloader_benchmark.py` | `X: TypeAlias = ...` → PEP 695 `type X = ...` |
| `src/maou/app/learning/multi_stage_training.py` | `TypeVar` → PEP 695 型パラメータ構文 |

`src/` の 4 ファイルは ruff の `target-version` が `requires-python` から
推論される結果，下限が 3.12 になると PEP 695 系ルール (UP040 / UP047 /
UP049) が有効化されて検出されるようになったもの．挙動は変わらない．


### なぜ 3.11 を落とすか

`requires-python` の下限を 3.11 に残したまま cp312/cp313 だけを出すと，
「宣言しているサポート範囲」と「実際に配る wheel」がずれる — 3.11 環境が
`pip install` に成功しつつ拡張が無い状態になり得る．DevContainer は既に
3.12 (`.devcontainer/devcontainer.json` の python feature) なので，
下限を 3.12 に揃えるのが宣言とビルドの一致として最小のずれになる．

### なぜ cshogi の下限を上げるか

cshogi 1.0.4 未満は `python_version >= "3.12"` に対して `numpy<1.27` を
課す．numpy 1.26 系に **cp313 wheel は無い**ため，Python 3.13 では
sdist ビルドに落ちて `uv sync` が失敗する．1.0.4 で制約が
`numpy>=2.1.0 (py>=3.13)` に分岐し，3.13 でも wheel が取れる．
結果として lock は python で fork し，3.12 → numpy 1.26.4 /
3.13 → numpy 2.5.2 になる (どちらも wheel あり)．
cshogi は dev 依存 (棋譜パーサ parity の oracle) のみなので，
配布 wheel のランタイム依存には影響しない．

### なぜ onnx を上げるか

旧 lock の onnx 1.20.1 を据え置いたまま 3.13 の fork を解決すると，
uv は 3.13 側に onnx **1.19.0** + ml-dtypes **0.4.1** を選ぶ．この組み合わせは
壊れており (`onnx/_mapping.py` が ml_dtypes 0.5 で入った
`float4_e2m1fn` を参照する)，ONNX を触る 6 テストが
`AttributeError: module 'ml_dtypes' has no attribute 'float4_e2m1fn'` で落ちた．
`uv lock --upgrade-package onnx --upgrade-package ml-dtypes` で
両 Python 共通の onnx 1.22.0 に揃え，解消した．
