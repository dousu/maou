# 提案: TimeStrategy の手数カーブ (中盤重み付け) を doc に反映する

user 指示「持ち時間戦略を中盤に時間消費が集中するように調整する．序盤は
指し手の分岐が起きにくい (定石化された指し手で学習が行われている) ので
探索時間を与えても結果があまり変わらない．終盤は dfpn による詰み判定が
入るので探索時間が少し短くても問題ない場合が少しある．フィッシャーや
秒読みでうまく戦略を調整する必要あり」．

コード側は実装済み (既定 off の A/B レバー)．doc 側の未反映分を本提案で
埋める．

---

## 何が変わったか

`allocate` の裁量枠にのみ手数依存の乗数を掛ける:

```
before: base = 残時間 / horizon        + byoyomi + inc − margin
after:  base = 残時間 / horizon × w(手数) + byoyomi + inc − margin
```

`w` は `peak_ply` を頂点とする山型の折れ線で，**底を序盤側と終盤側で
別に持つ** (既定 55 / 半幅 35 / 頂点 1.8 倍 / 序盤の底 0.7 倍 /
終盤の底 1.0 倍)．

設計上の要点は 3 つ:

1. **乗数は裁量枠 (バンクの取り崩し) にだけ掛け，毎手戻ってくる時間
   (秒読み・フィッシャー加算) には掛けない**．秒読みでは終盤の重みを
   下げても秒読み分が必ず残り，フィッシャーでは終盤が加算ペースに
   収束したうえでバンクを中盤へ寄せられる．三態の分岐を増やさずに
   両方が正しくなる．
2. **底が非対称**．序盤は「探索時間を与えても結果があまり変わらない」と
   強く言えるが，終盤は「少し短くても問題ない場合が**少し**ある」という
   弱い主張しか立たない．対称な山にすると，毎手戻ってくる時間が無い
   切れ負けで終盤が必要以上に痩せる (実測: ply 99 で 1.2s → 0.3s)．
   終盤の底を 1.0 倍 = 現行と同配分に置き，A/B の差分を中盤の山だけに絞る．
3. **自己正規化**．配分の土台が常にその時点の残時間の分数なので，カーブは
   配分を歪めるだけで総消費を増やす方向には倒れない．

## 実測プロファイル (実装を直接叩いたもの．100 手で決着 / margin 1s)

**A. 5 分切れ負け** (自分 50 手)

| ply | off | on |
|---|---|---|
| 1 | 6.5s | 4.2s |
| 21 | 4.8s | 3.6s |
| 51 | 3.0s | **5.7s** |
| 81 | 1.7s | 1.7s |
| 99 | 1.2s | 0.7s |
| 合計思考 | 165.4s | 181.9s |

**B. フィッシャー 3 分 + 5 秒**

| ply | off | on |
|---|---|---|
| 1 | 8.5s | 7.2s |
| 21 | 7.5s | 6.8s |
| 51 | 6.4s | **8.0s** |
| 81 | 5.6s | 5.6s |
| 99 | 5.3s | 5.0s |
| 合計思考 | 329.2s | 339.1s |

現行 (off) が **単調減少** = 初手が最も厚い配分だったことがこの計測で
はっきりした．`残時間 / horizon` は等比減衰なので，残時間が最大の初手が
必ず最大配分になる．カーブはこれを反転させて山を中盤へ移す．

## 未決として残すもの

- **棋力が上がるかは未検証**．VETO「レバーは A/B で確認してから既定化」に
  従い既定 off．GPU 自己対局での A/B が判定の場 (手が進むごとにノードが
  爆発する性質上，CPU 22 p/s では中盤の増分が棋力差にならない)．
- **パラメータ 5 個は A/B の出発点であって決着値ではない**．
- **`horizon_moves = 40` 固定に由来する未消化**が別にある．50 手指すと
  `(39/40)^50 ≈ 0.28` が構造的に残り，5 分切れ負けで 84.6s (off) /
  68.1s (on) を使い残す．終盤の底を 1.0 より上げると同じノブで末端消化を
  表現できるが，horizon 20 は過去の A/B で −89 Elo なので**速く使えば
  強い訳ではない**．本提案では触らない．

# 提案する doc 変更

## 1. `docs/design/usi-engine/index.md` §8.1

- 入力の記述「手数，(M2) 探索スナップショット」のうち**手数を実装済みに
  更新**する (現状は未配線のまま予定として書かれている)．
- 三態の式に `× w(手数)` を追加し，**乗数が裁量枠にのみ掛かる**ことと，
  その帰結 (秒読み・加算の床は削られない) を明記する．
- 底が非対称であることと，その理由 (序盤と終盤で主張の強さが違う /
  切れ負けには床が無い) を書く．
- 「定数は自己対局で調整 (未決)」の行に，カーブのパラメータも同じ扱いで
  あることを追記する．

## 2. `docs/design/usi-engine/verification.md` §4

- 未決 1 (想定残り手数) の隣に**未決: 手数カーブの棋力影響**を新設し，
  A/B 手順を書く: `--ab-mode timecurve` は持ち時間モード必須，
  GPU (L4) で `--clock-ms` を実戦相当に，n は Elo 分解能から決める
  (n=40 は ~150 Elo 級しか検出できない)．
- 既定 off の解除条件 (A/B で有意に勝つ) を明記する．

## 3. `docs/commands/usi.md`

- CLI 表に `--time-curve/--no-time-curve` と 4 つのパラメータを追加．
- `setoption` 表に `TimeCurve` (check，既定 off) を追加．**パラメータは
  setoption に出さない** (到着順が保証されないため CLI 側で固定する)．

## 4. `docs/commands/selfplay.md`

- `--ab-mode` の説明に `timecurve` (要 `--clock-ms`) を追加．
- カーブのパラメータ 4 つを表に追加し，**A/B の両者に同じ値が入り差は
  on/off だけ**であることを明記．

## 5. `docs/commands/floodgate.md`

- CLI 表にカーブの 5 オプションを追加．floodgate は 300+10F の
  フィッシャーなので**加算 10 秒がそのまま終盤の床になる**ことを書く．
