# analyze-gui を 3 カラムのワークベンチ (gr.HTML 1 枚) に作り替える

## Trigger

Claude Design (claude.ai/design) の handoff バンドル
`analyze-gui-workbench.dc.html` の実装依頼．user は 3 案 (3カラム /
盤面主役2カラム / 全画面盤面) のうち **1a 3カラム・ワークベンチ**を
選び，実装スコープとして次を指定した:

- 実装先: `dousu/maou` 本体
- 深さ: **gr.HTML 1 枚のフルワークベンチ** (Gradio コンポーネントを
  並べ替えるだけの案は不採用)
- 配線: キーボードショートカット / 盤面クリック分岐 / 悪手ジャンプ
  リスト / 全局面解析の進捗

デザイン検討時の user の課題認識 (handoff の chat 転記):

> 情報が縦に長く目的の場所を探しづらい／盤面が小さい・主役に見えない／
> グラフ・棋譜・候補手がタブで同時に見えない／解析の進捗・状態が
> 分かりにくい／分岐に入ったのか分かりにくい／見た目が素朴

## docs 側で直したい記述

### 1. §5 画面構成 (実装済み) — 全面差し替え

現行の記述はタブ 3 枚 (グラフ / 棋譜 / 候補手) + 左右 2 カラムの
ASCII 図で，実装と乖離する．新しい構成:

```
ヘッダー: maou 棋譜解析 / 読込元 / エンジン (mock 明示) / ショートカット
サマリ帯: 対局・一致率・平均勝率損失・詰み発見 (4 セル)
┌──────────────┬────────────────────────┬──────────────┐
│ 悪手ジャンプ  │ 本譜/分岐パンくず        │ 評価値グラフ  │
│ (しきい値可変) │ 盤面 (52px セル・矢印)   │ (SVG・クリック│
├──────────────┤ ナビ + 手数スクラバ      │  で手数移動)  │
│ 棋譜リスト    │ クリック状態 / 成・不成   ├──────────────┤
│ (損失・一致)  │ SFEN / position 文字列   │ 候補手 上位 N │
│ 現在手を追従   │ 合法手一覧 (L で開閉)    ├──────────────┤
│              │                        │ 解析パネル    │
└──────────────┴────────────────────────┴──────────────┘
```

タブは全廃し，グラフ・棋譜・候補手を常時同時表示にする
(user の課題「タブで同時に見えない」への対応)．

### 2. §6 に「悪手しきい値」を追記 — **延期決定の一部撤回**

§6 は 2026-07-16 の user 決定として

> 手の良し悪しの自動分類 (疑問手/悪手/大悪手のバッジ・グラフマーカー)
> は延期．勝率損失の閾値がモデル出力・探索アルゴリズムに依存して
> 変わり得るため，実モデルでの解析実績を見てから設計する

と書いている．今回のワークベンチは **勝率損失 ≥ しきい値**でフィルタ
した悪手ジャンプリストを持つので，この記述と衝突する．

ただし**延期の理由は温存している**と考える:

- 疑問手/悪手/大悪手の **3 段階分類も固定閾値も導入していない**．
  出しているのは「損失が閾値以上の手」という生値のフィルタ 1 本だけ．
- **閾値は UI 上で可変** (既定 0.10，見出しの数値を直接編集)．
  モデルが変われば user が動かせるので，「閾値を設計で固定する」
  という延期対象の判断を先送りしたままにできる．
- バッジ文言 (「疑問手」等) は一切付けず，数値のみを表示する．

提案する追記:

> 勝率損失の**閾値によるフィルタ** (悪手ジャンプリスト + 棋譜リストの
> 赤字) は実装する．閾値は UI 上で可変 (既定 0.10) とし，設計として
> 固定値を決めない．**段階分類 (疑問手/悪手/大悪手) とバッジ文言は
> 引き続き延期** — 分類の境界こそがモデル依存だから，という 2026-07-16
> の理由はそのまま生きている．

**この節は user の明示決定を部分的に上書きするため，承認を求める
最重要点**．承認されない場合は悪手リストを外し，キーボード
(⇧←/⇧→) のジャンプも落とす必要がある．

### 3. §6 グラフ実装の記述 — Plotly から SVG へ

現行:

> グラフ本体は Plotly (`go.Scatter`, コア依存) + `gr.Plot`．グラフ
> クリックでの局面ジャンプは gr.Plot 非対応の場合，ナビスライダーと
> 棋譜リスト行クリックで代替 (機能等価)．

ワークベンチではグラフを右レールに埋め込む必要があり，`gr.Plot` は
HTML 1 枚の中に置けないため **インライン SVG に置き換えた**．副産物
として §6 の「未決事項」だった**グラフクリックでの局面ジャンプが実現
した** (プロット領域のクリック → その手数へ，悪手の ● / 詰みの ★ は
個別にジャンプ)．縦軸は先手視点の勝率 / 評価値の 2 択に整理した
(後手視点は鏡映なので先手視点の読み替えで足りる，という §6 の説明は
そのまま)．

なお `interface/analysis_gui.py` の `eval_figure` (Plotly) は
**呼び出し元がなくなった**が，テスト付きの公開関数なので今回は残して
ある．本提案が承認され §6 が SVG に書き換わった時点で削除するのが
筋だと考える (削除は別 PR でよい)．

### 4. §10 のブリッジ記述 — レーン分割の追記

盤面クリック専用だったブリッジを，全 UI 操作を運ぶ
`data-action` 文字列の経路に一般化し，レーンを 5 本に分けた:

| レーン | 用途 | 直列化 |
|---|---|---|
| nav | ナビ・盤面クリック・分岐・表示オプション | なし |
| engine | 1 局面解析 / 再解析 | `concurrency_id="engine"` |
| engineAll | 全局面解析 (ジェネレータ) | 同上 |
| cancel | キャンセル | なし (実行中でも通す) |
| download | レポート JSON 保存 | なし |

§10 の «server_functions の `.change` は value 更新のみ反映され
`gr.update` の prop 更新が効かない» という実測メモは**今回むしろ
利点になった** — 出力が HTML 文字列 1 個なのですべて value 更新で済み，
`.then()` の連鎖が不要になった (成/不成ボタンと合法手一覧は HTML の
一部として描き直される)．この経緯も §10 に残したい．

## デザインからの意図的な逸脱

1. **盤面の座標 (筋/段の数字) を残した**．デザイン (`ShogiBoard.dc.html`)
   は座標を描いていないが，配布対象が「将棋を指す人」なので落とすと
   実用が下がると判断した．Modernist に合わせてバッジ地を外し，
   細い数字だけにしてある (`BoardTheme.show_coordinates` /
   `coordinate_badges` で戻せる)．
2. **しきい値・矢印・PV・候補手数の操作 UI を足した**．デザインでは
   これらは Claude Design の «Tweaks» (デザインツール側のつまみ) で，
   画面上の操作子ではなかった．旧 UI にはチェックボックス/スライダーが
   あったので，機能を落とさないよう見出しに小さな操作子として埋めた．
3. **悪手リストのジャンプ先は «その手を指す直前» の局面**にした
   (棋譜行クリックは従来どおり «指した後»)．悪手は指す前の局面で
   候補手矢印と見比べるのが目的なので，1 つずらしてある．
