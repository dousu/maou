# 探索値の出力をシャード化し，入力側を複数パス + Rust 読み出しにする

## 背景 (実測)

`maou utility search-values` は `flush_interval`(既定 500 局面) ごとに
**累積全体を書き直していた** (`search_value.py` の `_merge(done, fresh)` →
`df.write_ipc`)．書き込み量が行数の二乗で伸びる．

実測 (1 行 19.4 B):

| 行数 | 1 回の書き込み | 圧縮後 |
|---|---|---|
| 100,000 | 15.5 ms | 1.9 MB |
| 500,000 | 29.9 ms | 9.7 MB |
| 1,254,000 | 75.9 ms | 24.3 MB |

| 規模 | flush 回数 | 書き込み合計 | 探索時間に対する比 |
|---|---|---|---|
| 現行 1.25M | 2,500 | 約 100 秒 | 64 時間の 0.04% |
| ply>=120 の 5.3M | 10,600 | 約 28 分 | 37 時間の 1.3% |
| ply>=60 の 18.7M | 37,400 | 約 5.9 時間 | 130 時間の 4.5% |

dfpn TT のプール化で 1 局面の固定費が 9 分の 1 になった (PR #454) ため分母が
縮み，相対比重が上がる．メモリも 18.7M 行で `done` + `fresh` + concat 結果の
1.2 GB 前後が同時生存する．

また探索値の書き出しだけが Polars 経由で，パイプラインの他は
`maou._rust.maou_io` を通っていた (書き手と読み手で Arrow IPC の File/Stream
判定が揃わない余地がある)．

## 変更内容

### `utility search-values`

- `--output-path` は **シャードのディレクトリ**になる (旧: 単一 feather)．
  - flush は `pending_NNNNNNNN.feather` を 1 枚足すだけで既存に触れない．
  - 累積が `--shard-rows` に達したら**メモリ上の行から** `part_NNNNNNNN.feather`
    を 1 枚書いて pending を消す．各行はちょうど 2 回書かれるだけなので
    総 I/O は行数に比例する．
  - 「毎回 現在のシャードを書き直す」方式は採らない: シャードを大きくするほど
    二乗で重くなり，300MB シャード / 18.7M 行で約 10 時間になる．
- `--shard-rows` を追加 (既定 5,000,000 行 ≒ 97MB)．
- **`--resume` は前回の未確定シャードを引き継ぐ．** 引き継がないと (a) 前回の
  pending が永久に確定されず，(b) 蓄積カウンタが実行ごとに 0 へ戻るため，
  中断を繰り返すほど小さなファイルが溜まり続ける (レビュー指摘で発覚)．
- **実行の終わりでは目標行数に届かなくても確定させる．** 端数を pending の
  まま残して次回に育てさせる案もあるが，`--resume` のたびに `--shard-rows` が
  同じとは限らず，値が変われば「既存の確定シャードも分割し直すのか」という
  決着のつかない問題になる．実行ごとに閉じておけばその問いが発生しない．
  代償として**1 回の実行につき最低 1 枚**の確定シャードができる．
- 連番は 8 桁ゼロ詰めで，`--resume` は**既存の最大値の次**から振る
  (個数ではないので途中を手で消しても既存を上書きしない)．日時を使わないのは
  読み手が重複 id を「パス順で後勝ち」で解決するため — 固定桁の連番なら
  辞書順がそのまま探索順になる．
- 旧形式 (単一ファイル) を `--output-path` に渡すと**移行手順付きのエラー**に
  する．黙ってディレクトリ扱いすると既存の数日分をどう扱ったのかが見えない．
  ディレクトリへ移せば `--resume` がそのまま既探索として読む
  (シャード名に限らず配下の feather を全部読む)．
- 出力の拡張子チェックは不要になったので削除．

### `pre-process --search-value-path`

- **複数回指定できる** (click `multiple=True`)．別々に貯めた出力をまとめて
  渡せる．重複するパスは入口で畳む．
- 読み出しを **Rust バックエンド** (`rust_io.load_generic_df`) に変更．
  書き手も Rust になるので判定が揃う．
- 並び順を「旧形式 → 確定シャード (`part_*`) → 未確定 (`pending_*`)」に固定．
  素の辞書順では `search_values.feather` が `part_*` より後ろに来て，
  移行直後に**旧い値が新しいシャードを上書きする**．

## 破壊的変更

`--output-path` の意味が変わる (ファイル → ディレクトリ)．既存の呼び出しは
移行手順付きのエラーで止まる．黙って動作を変えるより安全だが，**CLI の
破壊的変更**であることは明記しておく．

版数は `pyproject.toml` を 0.85.1 → **0.86.0**．CLAUDE.md の規則では
「breaking change → major」だが，1.0.0 前なので minor で表す (user 判断)．
