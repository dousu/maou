# 提案: 詰み判定の攻守非対称を設計から解消する

user 指示「root dfpn の手番非対称問題に対して，探索部の設計部分から見直す．
より致命的な問題に関しては相手の手番でも自分の手番でも滑らかに判定できる
ようにしたい (相手の手番だけ詰みが見えていて，自分の手番評価では互角付近を
示すといったものは対局において致命的)．すべての leaf node で大きめの dfpn を
回すとコストがかかりすぎる．根本的な解決ができない場合はコストとなめらかさの
天秤でうまくバランスを取る」．

---

# 1. 現象 — selfplay 30 局の全数調査

`scratchpad/kifu.zip` (n=10) + `kifu2.zip` (n=20) の CSA を全数走査した．
CSA の `'** <score>` は着手側視点の評価値，`30000` は詰み確定を意味する．

| 指標 | 値 |
|---|---|
| 攻撃側が詰みを証明した局 | **28 / 30** |
| 守備側の認識遅れ (ply 数) の中央値 | 1 |
| 同 最大 | **11** |
| 守備側が最後まで気付かなかった局 | **3** |

最悪例 `kifu/game_0006.csa` の終盤 (T は消費秒，score は着手側視点):

```
ply117 +4647HI  T11  score   -141      ← 黒 (詰まされる側)
ply118 -0069GI  T2   score  30000      ← 白，2 秒で詰みを証明
ply119 +5869OU  T11  score    -70      ← 黒，11 秒使って互角判定
ply120 -3847UM  T2   score  30000
ply121 +0058GI  T11  score    -17
ply122 -4758UM  T1   score  30000
ply123 +6958OU  T11  score  +1170      ← 黒，「自分が優勢」と誤認
ply124 -0028HI  T1   score  30000
ply125 +0048GI  T11  score  +1156
ply126 -0066KE  T0   score  30000
ply127 +5566RY  T11  score  -2193
ply128 -0049GI  T0   score  30000
ply129 +5849OU  T0   score -30000      ← ようやく認識 (11 手遅れ)
```

**詰まされている側が「+1170 で優勢」と報告している**．しかも攻撃側は
T0〜T2 秒で即断，守備側は T11 秒の全予算を使って何も見つけていない．

さらに，この盲点区間の**黒はすべて王手中**である (合法手数 ply119=3 /
121=7 / 123=3 / 125=10 / 127=7 / 129=5，攻撃側は 200〜313 手)．
**分岐が極小の局面で 11 秒使って詰みを見落としている**．

# 2. 原因 — 3 つの非対称が重なっている

## A1. dfpn は「手番側が攻める」向きにしか呼べない

`rust/maou_shogi/src/dfpn/search/mod.rs:526`

```rust
self.attacker = board.turn;
```

`self.attacker` への代入は**コードベース全体でこの 1 行だけ**．root dfpn
(`maou_search/src/search.rs:1638-1664`) も leaf-mate (`search.rs:1223-1228`)
も，解いているのは常に「手番側が詰ませられるか」であり，
**「手番側が詰まされるか」を問う経路は存在しない**．

## A2. 詰み探索の出力と，木の即時伝播規則が噛み合っていない

`tree.rs` の確定値伝播は OR / AND 両方が実装済みだが，
**即時に発火するのは「子が `cv = 0.0`」の OR ルールだけ** (`search.rs:1032`)．
一方，詰み探索が注入できるのは `proven::WIN` (= その葉の手番側の勝ち，親から
見て `cv = 1.0`) **のみ**であり，親を確定させるには全兄弟の確定 (AND 集約)
が要る (`search.rs:1009`)．

したがって `proven::LOSS` の発生源は 3 つしかない:

1. 合法手ゼロ (`search.rs:1211`)
2. 連続王手の千日手 (`search.rs:1193`)
3. `aggregate_proven` で全子が WIN

**詰み探索から LOSS が入る経路は存在しない**．この欠落を攻め側でだけ
埋め合わせているのが root dfpn であり，**守備側には対応物がない**．

## A3. 確定値が PUCT に入らず，走行平均に希釈される

PUCT ループ (`search.rs:1099-1123`) は `child.wins() / child.visits()` しか
見ず，`proven_value()` は `skip_proven_children` (既定 false) の除外判定に
しか使われない．確定ノードは再訪のたびに 0/1 を backprop するだけで，証明前
に貯めた NN 由来の `wins` が残る．
さらに **mate distance を保持するフィールドが存在しない** — 確定値は
`0.0 / 0.5 / 1.0` の三値のみで，短い詰みと長い詰みを区別できない．

# 3. 測定 — 「守備は高い」という前提は成り立たない

`game_0006` の局面に対し dfpn を直接叩いて実測した (**debug ビルドのため
壁時計は報告しない．ノード数はビルド非依存**)．

## 3.1 守備側 AND-root のコスト ≒ 攻め側 OR-root のコスト

ply119 (黒番・王手中・合法手 3) で各合法手を攻め方 dfpn にかけた:

| 黒の応手 | 結果 | ノード数 |
|---|---|---|
| 5h5i | 詰み (mate-1) | **2** |
| 5h6h | 詰み (mate-3) | **10** |
| 5h6i | 詰み (mate-39) | 314,714 |
| **合計 (AND-root 相当)** | **詰まされ確定** | **≈ 314,726** |

比較: 攻撃側が ply118 で同じ詰みを証明したコストは **321,508 ノード**．

**守備の証明は攻めの証明とほぼ同コスト**である．非本命の応手はすべて数〜十
ノードで反証されるため，コストは「攻め側も解かねばならない 1 本の本命枝」に
支配される．**分岐数 × 攻め方コスト にはならない**．

## 3.2 攻守のコストは逆相関する (= 両方向を回しても足し算にならない)

ply119 で現行どおり攻め方向 root dfpn を回すと:

```
status=no_checkmate  nodes=1  stop=disproven
```

**1 ノードで終わる**．詰まされている局面では攻め方向探索は即死し，
**2,000,000 ノードの予算が丸ごと未使用**になる．
逆に自分が優勢な局面では攻め方向が高くつき，守備方向 (§3.3) が数十ノードで
片付く．**両方向を回した合計コストは max に近く，sum ではない**．

## 3.3 非王手局面の詰めろ検出 (null-move プローブ) は安全な局面ではほぼ無料

手番を相手に渡して攻め方 dfpn を回す (= 「パスしたら詰むか」):

| ply | 合法手 | 結果 | ノード数 |
|---|---|---|---|
| 105 | 112 | 詰めろなし (反証) | **43** |
| 107 | 164 | 詰めろなし (反証) | **46** |
| 109 | 159 | 詰めろなし (反証) | 13,181 |
| 113 | 154 | 詰めろなし (反証) | 871,886 |
| 111 | 101 | 不明 (予算切れ) | 1,500,000+ |
| 115 | 4 (王手中) | **mate-17 の脅威を検出** | **859** |
| 117 | 4 (王手中) | **mate-7 の脅威を検出** | **86** |

**ply115 の時点で 859 ノードあれば「自分が詰めろを掛けられている」と分かった**．
実際の黒はそこで 11 秒探索して −179 と報告している．
コストは危険な局面に集中せず，むしろ**危険な局面ほど安い**．
ただし ply111 のような**反証が高くつく裾が存在する** — 予算切れ (`unknown`)
は「情報なし」として NN 評価にフォールバックすればよく，安全側に倒れる．

# 4. 設計

## 4.1 根本解決の柱 — dfpn に攻め方を明示指定できるようにする

`self.attacker = board.turn` を，solver に持たせた `root_attacker:
Option<Color>` で上書き可能にする．探索コアは `board.turn == self.attacker`
の**相対判定に統一されており** (`search/mod.rs:1281` の 1 箇所)，
`depth % 2` のような絶対位置依存はない．したがって root を AND ノードに
しても探索・TT・proof_hand・heuristics は無改修で追従する．

これが「なめらかさ」の根 — **同じ局面を攻守どちらから問うても，同じ探索器が
同じ答えを返す**．

要注意 (soundness):

1. **`verify_proof` の無駄合いフィルタ** (`dfpn/search/pv.rs:269`) は
   「AND ノード = 王手中 ⇒ 駒打ちは必ず合駒」を前提にしている．
   root AND ノードは王手中とは限らないので誤除外し得る．
   `board.is_in_check()` でガードする．
2. **`find_shortest` の終端条件** (`search/mod.rs:604-607`) が `d <= 1` =
   奇数手数前提．AND root では偶数手数になる．
3. **TT を solve 間で再利用するなら attacker 色をキーに含める**必要がある
   (`hand` フィールドが「攻め方持駒」という意味を持つため)．現状は毎回
   再確保なので即時の問題はない．

## 4.2 段階的な組み込み — コストとなめらかさの天秤

「全 leaf で大きい dfpn」は採らない．以下の 4 段で，**コストを危険な局面に
集中させる**．

### 段 0 — 確定値の伝播を直す (コスト増ほぼゼロ，最優先)

- 詰み探索が **`proven::LOSS` を注入できる**ようにする (防御方向の証明が
  付いたノード)．A2 の欠落を塞ぐ．
- **mate distance を保持する**．確定値を三値から「符号付き手数つき」に拡張し，
  短い詰み・長い受けを選べるようにする．現在 score が flat な 30000 なのも
  ここに由来する．
- **proven-aware PUCT**: 確定 WIN の子は即選択，確定 LOSS の子は候補から
  除外，確定値は走行平均に混ぜない．
- 副産物として **terminal spin (既知 97.6%) が同時に減る**．

### 段 1 — 王手中の防御 dfpn (安い・高価値)

自分が王手されている root / leaf では合法手が 3〜10 手 (§1)．
そこで**防御方向 AND-root dfpn** を回す．

- root: 攻め方向 dfpn が `disproven` で即死した分の予算をそのまま回す
  (§3.2 より実質追加コストなし)．
- leaf: 王手中の葉に限定し，小予算 (現行 `leaf_mate_nodes = 50` に対し
  2,000〜20,000 程度) を与える．
- **観測された盲点 6 局面はすべてこの条件に該当する**．

### 段 2 — 非王手局面の詰めろプローブ (null-move)

「パスしたら詰むか」を既存の攻め方 dfpn そのままで解く (手番反転のみ)．
安全な局面では 43〜46 ノード (§3.3)．発火したら段 1 の防御 AND-root へ昇格．

- `Board::set_turn` は hash を O(81) 全再計算するため，hot path 用に
  **incremental な null-move (`hash ^= ZOBRIST.turn_hash()`) を追加する**．
- 王手中には適用しない (玉取りで自明に詰むため意味がない)．
- 予算切れ (`unknown`) は「情報なし」＝ NN 評価にフォールバック．

### 段 3 — 訪問数による昇格と TT 再利用

- visit 閾値を超えた葉だけ予算を上げる (現行 50 ノードでは 1〜3 手詰しか
  拾えない)．root と PV 上のノードは毎 `go` で防御 dfpn．
- root dfpn は `go` ごとに 4M エントリ (~256MB) を確保・ゼロ初期化している．
  攻守 2 本走らせるなら **solve 間の TT 再利用** (attacker 色をキーに含める)
  が下支えとして効く．

## 4.3 新設するノブ

| 名前 | 既定 | 意味 |
|---|---|---|
| `defensive_mate` | true | 防御方向詰み探索の有効化 |
| `defensive_mate_nodes` | 攻め残余を流用 | root 防御 AND-root の予算 |
| `threat_probe_nodes` | 20,000 | 非王手局面の詰めろプローブ上限 |
| `leaf_defensive_mate_nodes` | 2,000 | 王手中の葉の防御予算 |
| `mate_escalate_visits` | (段 3) | 葉の予算を上げる visit 閾値 |

A/B 用に `--ab-mode defmate` を追加する
(**列挙は Rust / Python / click の 3 箇所**．`test_ab_modes.py` が pin)．

# 8. 実装時に確定した差分 (承認後の追記)

承認後の実装と実測で，§4 の設計から次の 3 点が変わった．いずれも
**user の追加質問がきっかけで判明した欠落**なので，経緯ごと残す．

## 8.1 root 候補手の敗着フィルタを追加した (段 1 の拡張)

user 質問「詰み局面ではもうどの応手をしても変わらないと思いますが，詰みの前の
局面では相手が詰ませることができることを踏まえた応手の選定が行われるか」．

実測すると，**負けは「詰んでから見えなかった」のではなく，まだ受かる局面で
敗着を選んだ時点で決まっていた**．game_0006 の先手番を順に受け方向で解くと
ply117 までは safe，ply119 で詰み確定．その ply117 の 4 手を一つずつ
「指した後に相手が詰ませられるか」で判定すると:

| ply117 の手 | 判定 |
|---|---|
| **4f4g (対局で選んだ手)** | **LOSES (mate-41)** |
| 5h5i | LOSES (mate-1) |
| 5h6h | LOSES (mate-29) |
| **5h6i** | **safe** |

この帯は §4 のどの機構にも掛からない — root 受け方向 dfpn は「既に詰んで
いる」ときしか発火せず，木の proven 伝播は葉の小予算では mate-29/41 を証明
できない．よって **root の各合法手について攻め方向 dfpn を回し，敗着を
`proven = Some(0.0)` に畳んで既存の負け確定除外に合流させる**機構を追加した．

- **`find_shortest=false` が必須**．既定 (true) は最小性を確定できないと
  `Unknown` を返すため，同じ局面が「不明」に化けて敗着を見逃す (実測)．
- **予算は段階的に配る** (`nodes/50` → `nodes/5` → `nodes`)．1 手ずつフル
  予算だと重い手に吸われ，後ろの手が未検査のまま打ち切られる — 未検査は
  「安全」ではなく「未知」なので敗着が素通りする．
- 合法手 ≤ 16 で gate (実測した敗着局面の合法手は 3〜10)．

## 8.2 並列化を入れた

user 指示「実行環境によっては CPU の稼働が結構空いてることもあるので dfpn が
動作するスレッドを増やせば多めの予算で効率的に検証できたりする」．

子ごとの判定は独立なので `defensive_mate_threads` (既定 1) を追加．実測:

| 局面 | 1 スレッド | 2 | 4 |
|---|---|---|---|
| ply117 (4 子，うち 1 子が mate-41) | 3,152ms | 1,935ms | 1,927ms |
| ply125 (10 子，全て詰み) | 653ms | 488ms | 413ms |

**天井は「最も重い 1 子」**なので，並列度は子の数が多いときに効く．
スレッドと予算は補完関係 — 並列度で多子のコストを吸収し，その分
`root_child_filter_nodes` を上げて最も重い子にノードを回す．

## 8.3 実バグを 1 件修正した

受け方向 root は**非王手で全合法手を生成する**ため合法手が 64 を超える．
`BitSet64::test/reset` が `1u64 << i` で shift overflow して panic した．
攻め方向では AND ノードが常に王手中なので踏まなかった潜在バグ．
64 以降は sum 集計扱い (δ 過大 = 保守側) に倒した — bit を落とす操作は
δ を sum から max へ緩める最適化にすぎず，落とせなくても健全性は保たれる．

# 9. 見送った項目 (理由つき)

- **proven-aware PUCT (確定値を Q に直接注入)**: §2 の A3 に対する策として
  挙げたが実装しない．重複する `--skip-proven` レバーが **GPU 発火測定で
  棄却済み** (`reviews/2026-07-27-spin-levers-gpu-verdict.md`) であり，
  再導出になる．**受け方向 leaf-mate が `proven::LOSS` を注入すれば既存の
  OR ルールで 1 手で親に伝播する**ので，観測された病理はこちらで塞がる．
- **木の中の mate distance**: 最長抵抗の選択は root 受け方向 PV と敗着
  フィルタで得られるため，`Node` を太らせる (808B/node の invariant) 必要が
  なかった．USI の `score mate N` 報告を入れる段階で再検討する．
- **段 2 (非王手局面の詰めろプローブ)**: 別 PR．null-move の incremental 実装
  (`Board::set_turn` は O(81) 全再計算) が前提になる．
- **AND-root と敗着フィルタの重複探索**: 合法手 ≤ 16 のときフィルタの結果
  だけで「全子が負け = 詰み」も最長抵抗手も導けるので AND-root を畳める．
  AND-root が安い側 (安全な広い局面で 33〜50ms) なので今回は放置する．
